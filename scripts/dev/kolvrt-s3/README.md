# Dev S3 на kolvrt

Отдельный Compose-проект `dev-s3`, SeaweedFS 4.48 с закреплённым digest.
Использует существующие Docker/Compose и Python 3; пакеты на хост не устанавливаются.
Конфигурация: `/srv/services/dev-s3`, данные и метаданные: `/srv/data/dev-s3/data`.
Контейнер работает как UID/GID 10001, с read-only root, tmpfs, без capabilities,
с лимитами 1 CPU / 1 GiB RAM. Логи: три файла до 10 MiB.

S3 слушает `127.0.0.1:8333`; служебные HTTP/gRPC порты также только loopback:
`18333`, `8888`, `18888`, `9333`, `19333`, `9340`, `19340`.
`network_mode: host` исключает публикацию localhost-портов старым Docker.
Admin UI, WebDAV, IAM API, Iceberg/Lance и телеметрия выключены.
Это доверенный dev-хост: SSH-пользователи и администраторы хоста имеют доступ
к внутренним интерфейсам SeaweedFS. Это не изоляция от недоверенных пользователей.

Бакет `wildrift-dev`; ключ приложения ограничен этим бакетом. Его credentials:
`/srv/services/dev-s3/credentials/wildrift.env`, доступны SSH-пользователю.
Административный ключ остаётся в root-only каталоге `secrets`.
Повторная установка сохраняет ключи и данные. При частично созданных credentials
скрипт отказывается продолжать, не меняя существующий ключ.

Скопировать эту папку на сервер и один раз выполнить:

```sh
sudo python3 /path/to/kolvrt-s3/manage.py install --owner life
```

Инициализация бакета, public-read policy и CORS выполняется `npm run dev:setup`
с рабочего ПК. Повторная инициализация не удаляет объекты. Public-read разрешает
просмотр файлов через SSH-туннель; анонимная запись и listing не разрешены.

Управление:

```sh
sudo python3 /srv/services/dev-s3/manage.py status
sudo python3 /srv/services/dev-s3/manage.py logs
sudo python3 /srv/services/dev-s3/manage.py stop
sudo python3 /srv/services/dev-s3/manage.py start
sudo python3 /srv/services/dev-s3/manage.py backup
```

Docker `restart: unless-stopped` поднимает сервис после перезагрузки хоста.
Остановка локального сайта закрывает его туннель, серверный S3 продолжает работать.
Ручной туннель: `ssh -N -L 127.0.0.1:3390:127.0.0.1:8333 kolvrt`.
Локальное приложение продолжает использовать `http://127.0.0.1:3390`.

Ручной `backup` кратковременно останавливает **только dev-s3**, архивирует файлы
вместе с метаданными и конфигурацией, проверяет gzip CRC и атомарно публикует архив
в `/srv/data/dev-s3/backups`. Затем восстанавливает предыдущее состояние сервиса.
Архивы содержат секреты и доступны root; автоматической ротации и расписания нет.
Копии на том же диске не защищают от его поломки. Restore выполняется вручную
при остановленном dev-s3 из целого архива, а не только отдельных volume-файлов.
64 тома по 128 MiB ограничивают рост blob-томов, но не являются квотой всего
каталога: метаданные, журналы и архивы требуют отдельного контроля диска.

Данные не удаляются командами управления. Продакшен-S3 и другие Compose-проекты
этот комплект не изменяет. Обновления образа — отдельно с резервной копией.

Документация: [S3 API](https://github.com/seaweedfs/seaweedfs/wiki/Amazon-S3-API),
[ключи и права бакетов](https://github.com/seaweedfs/seaweedfs/wiki/S3-Credentials).
