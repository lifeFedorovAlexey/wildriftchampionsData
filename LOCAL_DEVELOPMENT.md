# Локальная разработка

Из корня `D:\wildRiftChampions`:

```powershell
npm run dev:up       # запустить в фоне без новых окон
npm run dev:status   # проверить сервисы, БД и таблицы
npm run dev:logs     # последние строки общего лога
npm run dev:logs -- auth
npm run dev:down     # остановить свои процессы, сохранить данные
```

Сайт: **http://127.0.0.1:3300**. Панель разработки: **http://127.0.0.1:3399**.
В панели доступны состояние сервисов, логи, таблицы БД и кнопки входа тестовым
игроком и администратором. Пользуйся именно `127.0.0.1`: cookies не переносятся
между ним и `localhost`. Администратор получает и пользовательскую сессию,
поэтому можно проверять профиль, чат и создание квизов.

`npm run dev` запускает тот же набор в текущем терминале. Ctrl+C останавливает
процессы. UI обновляется через Next HMR, API и чат — через `node --watch`.
Падение одного процесса останавливает остальные и остаётся в логах.

## Первый запуск на новом ПК

Нужны Node.js >=22.12, npm, OpenSSH и SSH alias `kolvrt` с работающей
авторизацией по ключу. PostgreSQL и S3 работают на kolvrt; Docker на рабочем ПК
для обычного запуска больше не нужен. Сначала проверь
`ssh kolvrt hostname`. `wr-api/` и `wr-chat/` — отдельные репозитории;
они должны находиться рядом с `ui/`, как в текущем checkout.

```powershell
npm ci
npm --prefix ui ci
npm --prefix wr-api ci
npm --prefix wr-chat ci
```

Один раз на сервере создать отдельную базу (для текущего окружения уже создана):

```powershell
ssh -t kolvrt "sudo python3 /srv/services/dev-postgres/manage.py create-project wildrift"
```

Dev-S3 на kolvrt тоже должен быть установлен; для текущего окружения это уже
сделано. Конфигурация и команды сервера: [Dev S3](scripts/dev/kolvrt-s3/README.md).

После этого:

```powershell
npm run dev:setup
npm run dev:seed  # необязательно: перенос игровых данных из старой локальной БД
npm run dev:up
```

`dev:setup` скачивает `/srv/services/dev-postgres/credentials/wildrift.env` через
SCP в `.runtime/dev/database.env`, а `/srv/services/dev-s3/credentials/wildrift.env`
в `.runtime/dev/storage.env`. Генерирует отдельные случайные секреты приложения,
открывает SSH-туннели, настраивает dev-бакет/CORS и применяет схему. Credentials и секреты
сохраняются. Перед повторной настройкой останови локальные сервисы.
Обычный запуск не выполняет миграции или синхронизацию данных автоматически.

## Порты и данные

| Сервис | Адрес |
| --- | --- |
| UI / Next dev | `127.0.0.1:3300` |
| API gateway | `127.0.0.1:3301` |
| Public API | `127.0.0.1:3302` |
| Auth API | `127.0.0.1:3303` |
| WebSocket chat | `127.0.0.1:3310` |
| SSH → S3 / SeaweedFS на kolvrt | `127.0.0.1:3390` → серверный `127.0.0.1:8333` |
| Панель разработки | `127.0.0.1:3399` |
| SSH → PostgreSQL на kolvrt | `127.0.0.1:15432` |

Все слушают loopback. Занятый порт приложения вызывает ошибку; чужие процессы не
завершаются. Если `15432` уже занят, проверяются имя БД, роль, владелец и права.
Если занят `3390`, проверяется доступ к dev-бакету отдельными серверными ключами.
Подходящие существующие туннели используются, но не закрываются при остановке.

База `wildrift_dev`, роль `wildrift_app`. Данные подключения для DBeaver/DataGrip:
`.runtime/dev/database.env`. Туннель работает, пока запущен набор сервисов.
Его также можно открыть отдельно командой из инструкции PostgreSQL.

Секреты приложения: `.runtime/dev/secrets.json`; ключи dev-S3:
`.runtime/dev/storage.env`. Логи: `.runtime/dev/logs/`:
`supervisor`, `ui`, `public`, `auth`, `gateway`, `chat`, `tunnel`, `storage-tunnel`.
У запросов логируются метод, путь без query, статус и длительность.
Тела запросов, cookies и токены не журналируются. Логи сервисов ограничены
10 MiB + один предыдущий файл; общий лог сохраняется с предыдущего запуска.
Просмотр в реальном времени:

```powershell
Get-Content .runtime/dev/logs/auth.log -Tail 50 -Wait
npm run dev:logs -- storage-tunnel
ssh -t kolvrt "sudo python3 /srv/services/dev-s3/manage.py logs"
```

На kolvrt работает отдельный Docker-проект `dev-s3`; данные и метаданные находятся
в `/srv/data/dev-s3/data`. S3 нужен для аватаров, вложений и квизов.
Бакет `wildrift-dev` разрешает чтение файлов через туннель, запись требует
отдельных dev-ключей; CORS разрешён только для UI. Ключи ограничены dev-бакетом.
Образ [SeaweedFS](https://github.com/seaweedfs/seaweedfs) закреплён digest в Compose.
`dev:down` закрывает собственные туннели; PostgreSQL и S3 на kolvrt продолжают
работать. Серверный S3 автоматически запускается вместе с Docker, если его
не остановили вручную. Ручной backup описан в инструкции серверного S3.

Прежний контейнер `wildrift-local-storage-s3-1` на рабочем ПК остановлен, его том
`wildrift-local-storage-data` сохранён для отката. Существовавшие файлы перенесены
на kolvrt с проверкой содержимого; адреса файлов остались прежними.

## Наполнение

`dev:seed` читает **только прежнюю локальную** `127.0.0.1:5434/wr_api`, используя
credentials из `wr-api/.env`. Соединение открывается read-only, данные читаются
в согласованном snapshot. Список копируемых игровых таблиц задан явно в
`scripts/dev/database.mjs`: чемпионы, статистика, гайды, патчи, справочники и скины.
Пользователи, идентификаторы OAuth, сессии, сообщения чата, результаты квизов и
другие пользовательские данные не переносятся. Целевые игровые таблицы должны
быть пустыми; при повторном запуске команда откажется, сохранив изменения.
Все таблицы копируются одной транзакцией, отчёт — `.runtime/dev/seed-report.json`.

Текущий источник содержит статистику по **10 апреля 2026**, 137 чемпионов,
147 гайдов и 115 патчей. Это данные для проверки интерфейса, не обещание
актуального игрового состояния. Свежий продакшен-дамп для запуска не требуется.
Копирование прода этим инструментом намеренно не автоматизировано.

Игровые изображения с уже сохранёнными публичными URL могут загружаться из
интернета. Создаваемые локально пользовательские файлы отправляются в dev-S3
на kolvrt. Внешний OAuth и Telegram-уведомления не настроены: для разработки используй
тестовый вход в панели. Генераторы ИИ и периодические импорты сами не запускаются.

## Изоляция от продакшена

- Обычные `.env`, `.env.local` и настройки деплоя не меняются. CI дополнительно проверяет изоляцию локального запуска.
- Дочерние процессы получают отдельное окружение; значения из обычных env-файлов
  перекрываются, production-секреты и Node preload hooks не наследуются.
- Для БД допустима только `wildrift_app@127.0.0.1:15432/wildrift_dev`, без query
  overrides; перед миграциями, копированием и стартом проверяются права роли.
- Для S3 допустимы только dev-ключ `wildrift-dev`, бакет `wildrift-dev` и endpoint
  `http://127.0.0.1:3390`. Production endpoint и административный ключ отвергаются.
- Пулы API ограничены двумя соединениями с учётом лимита роли в 10 соединений.
- Тестовый вход живёт в отдельном локальном supervisor, не в маршрутах приложения.
- Изменения CSP/HMR/локальных картинок требуют одновременно
  `NODE_ENV=development` и `WR_LOCAL_DEV=true`. В production политика прежняя.
- `NODE_ENV=production` запрещает команды запуска разработки.
- Сборка разработки использует `ui/.next-local`; production `.next` не затрагивается.
- `.runtime/` уже исключён из Git. Не коммить credentials, дампы и файлы S3.

Проверка ограничений: `npm run dev:test` и `npm --prefix ui test`.
Для запущенного окружения: `npm run dev:smoke` проверяет API, настоящие
тестовые сессии, WebSocket, подписанную загрузку в S3, CORS, запрет анонимной
записи/listing и доступа к чужим бакетам, а также HTML восьми страниц.
`npm run dev:smoke -- --browser` дополнительно проверяет страницы в Chromium
и сохраняет скриншот; требуется установленный браузер Puppeteer или Edge.

Если SSH недоступен — проверь, что kolvrt включён, alias и ключ работают.
Для диагностики обрывов можно держать туннель в отдельном обычном PowerShell:

```powershell
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -L 127.0.0.1:15432:127.0.0.1:5432 -L 127.0.0.1:3390:127.0.0.1:8333 kolvrt
```

После этого `npm run dev:up` использует его. Закрывай такой туннель вручную,
когда локальная работа закончена. Если соединение регулярно обрывается,
проверь, не перехватывает ли VPN маршрут к локальной сети с `kolvrt`.

Если запуск оборвался — `npm run dev:logs`, затем лог нужного сервиса.
`dev:down` не удаляет БД, тома или данные и не делает глобальную очистку Docker.
